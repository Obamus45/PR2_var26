# Вариант 26 — этапы 1–2

CLI-приложение на Python читает YAML-конфигурацию, проверяет пользовательские параметры и для этапа 2 получает прямые зависимости пакета из формата Ubuntu APT. Индексы репозитория загружаются и разбираются собственным кодом на стандартной библиотеке Python — `apt`, `dpkg`, сторонние библиотеки для получения зависимостей не используются.

## Параметры конфигурации

| Ключ YAML | Назначение | Проверка |
|---|---|---|
| `package_name` | Имя анализируемого пакета | Непустое; латинские буквы, цифры, `.`, `+`, `_`, `-` |
| `repository` | URL Packages-индекса / каталога suite либо путь к локальному тестовому Packages-файлу | В тестовом режиме — существующий файл; иначе — корректный HTTP(S)-URL поддерживаемого вида |
| `test_mode` | Читать локальный тестовый индекс вместо сети | Только YAML boolean `true` или `false` |
| `output_file` | Имя файла изображения графа | Только имя файла с расширением `.svg` |
| `ascii_tree` | Флаг ASCII-дерева (используется на более позднем этапе) | Только YAML boolean `true` или `false` |
| `filter_substring` | Подстрока фильтрации (используется на более позднем этапе) | Строка; пустая строка отключает фильтрацию |

Все шесть параметров обязательны. На этапе 2 программа выводит настройки, а затем — найденные `Pre-Depends` и `Depends`. Если в строке `Depends` есть альтернативы, например `foo | foo-compat`, они выводятся одной группой, так как это варианты одного требования, а не две обязательные зависимости.

## Установка и запуск

Нужен Python 3.10+.

```bash
python -m pip install -r requirements.txt
python app.py
```

По умолчанию приложение использует `config.yaml`. Для другого YAML-файла:

```bash
python app.py --config путь/к/config.yaml
```

## Тестовый режим без сети

В поставляемом `config.yaml` включён `test_mode: true`. Файл `test-repository.txt` содержит учебные записи в формате Ubuntu `Packages`. Запустите `python app.py` из каталога проекта. Ожидаемый фрагмент вывода:

```text
Прямые зависимости Ubuntu APT для пакета demo-app (версия 1.2.3-1):
Pre-Depends:
  - init-system-helpers
Depends:
  - libc6
  - demo-core | demo-core-compat
  - demo-data
```

Относительный путь к тестовому файлу задаётся относительно самого файла конфигурации.

## Получение из Ubuntu-репозитория

Поле `repository` не содержит отдельного параметра выпуска Ubuntu, поэтому укажите либо URL конкретного APT Packages-индекса, либо URL каталога конкретного suite. Например, для Ubuntu Noble:

```yaml
package_name: bash
repository: https://archive.ubuntu.com/ubuntu/dists/noble/
test_mode: false
output_file: bash-dependencies.svg
ascii_tree: false
filter_substring: ""
```

В файле `config-ubuntu.example.yaml` уже есть рабочий пример для пакета `bash`. Запустить его можно так:

```bash
python app.py --config config-ubuntu.example.yaml
```

Можно указать URL непосредственно на индекс, например `https://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.gz`. Для каталога suite приложение читает `Release`, берёт список компонентов и архитектур (предпочитает `amd64`) и ищет пакет в соответствующих индексах `Packages`. Поддерживаются обычный, `.gz`, `.xz` и `.bz2` индексы. URL корня зеркала (`https://archive.ubuntu.com/ubuntu/`) сам по себе не указывает выпуск Ubuntu, поэтому приложение просит задать suite в адресе.

Обратите внимание: `filter_substring`, `ascii_tree` и `output_file` проверяются и показываются, но логика фильтрации, дерева и генерации SVG относится к последующим этапам.

## Ошибки

Неверная/отсутствующая YAML-конфигурация и некорректные пользовательские значения выводятся в stderr. Ошибки загрузки индекса, неподдерживаемый URL или отсутствие пакета выводятся отдельно как `Ошибка получения данных APT`; успешная конфигурация при этом завершается с кодом `1` при ошибке APT, `2` при ошибке конфигурации.

## Тесты

```bash
python -m unittest -v
```

Проверяются валидации этапа 1, чтение control-записей Ubuntu Packages, разворачивание зависимостей с переносами строк, альтернативы, сжатый локальный индекс и отсутствие искомого пакета. Сетевые тесты не требуются.
